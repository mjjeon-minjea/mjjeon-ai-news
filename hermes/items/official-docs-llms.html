Hermes 공식 문서 색인: 세션 DB 복구·WAL 보존 지침 확인

Hermes Agent

공식 Docs의 운영 참고 정보 보완으로 게시합니다. 공식 llms.txt와 NousResearch 공식 repository를 직접 조회했으며, 리디렉션을 따르는 GET으로 최종 URL https://hermes-agent.nousresearch.com/docs/llms.txt 및 https://github.com/NousResearch/hermes-agent 모두 HTTP 200을 확인했습니다. 색인에 연결된 Session Storage Recovery 본문에서 이전 WAL 사본 보유에 따른 쓰기 거부, 관련 프로세스 종료 후 점검하는 복구 순서, WAL·SHM 삭제 금지 및 세션 최적화의 동시 사용 거부 조건을 직접 확인했습니다. 제공된 기존 게시 요약 대비 데이터 보존과 복구 판단에 필요한 구체적 운영 정보를 보완하므로 meaningful change로 판단합니다. 이전 원문과의 행 단위 차이는 제공되지 않았으므로 해당 문서의 신설 시점이나 기능 도입 시점은 확정하지 않습니다. 공식 Releases 본문과 실제 설치 버전은 이번 검토에서 확인하지 않았으며 신규 출시·보안 사고·breaking change를 주장하지 않습니다. 보안·breaking·교차신호 조건은 escalation 검토 후보로만 취급하고 발생을 확정하지 않습니다.

핵심 요약

Hermes Agent 공식 llms.txt와 연결된 Session Storage Recovery 문서 본문을 직접 확인했습니다. 문서는 다른 프로세스가 이전 WAL 사본을 붙잡은 상황에서 세션 쓰기를 중단하는 보호 동작을 설명하고, 해당 프로필의 모든 관련 프로세스를 종료한 뒤 doctor로 보유 프로세스를 확인하고 재시작하는 복구 순서를 안내합니다. WAL·SHM 파일 삭제와 DB 본체만 복사하는 방식은 피하라고 명시합니다. 실행 중인 다른 프로세스가 DB를 사용하는 경우 세션 최적화 명령을 거부하는 조건도 안내합니다. 기존 게시의 LLM 없는 예약 작업·결과 전달 안내에 세션 데이터 보존을 위한 운영 참고 정보를 보완합니다. 문서 정보 확인이며 신규 릴리스나 설치 버전 변경을 뜻하지 않습니다. 원문 시각은 후보의 문서 Last-Modified 기준이며 기능 출시일이 아닙니다.

왜 중요

Gateway·Desktop·대시보드·예약 작업이 같은 프로필의 세션 저장소를 사용할 때, DB 재작성과 WAL 삭제를 단순 정리 작업으로 취급하면 대화 데이터 보존에 영향을 줄 수 있습니다. 쓰기 거부 오류를 무작정 우회하거나 일부 프로세스만 재시작하기 전에 확인할 공식 복구 경로라는 점에서 운영상 의미가 있습니다. 현재 운영 환경에서 해당 오류가 발생했다는 뜻은 아닙니다.

우리 영향

기존 게시 요약에 없던 세션 저장소 복구 순서와 WAL 보존 주의사항을 공식 문서 본문으로 보완하는 뉴스 갱신입니다. 이번 작업은 출처 확인과 뉴스 게시에 한정하며 실행 중인 Hermes의 버전·설정·권한·네트워크·컨테이너·예약 작업·세션 DB를 변경하지 않습니다. 실제 장애 재현, 복구 실행 및 설치 환경별 동작은 검증하지 않았습니다.

지금 할 일

세션 쓰기 거부나 저장소 유지보수를 검토할 때 https://hermes-agent.nousresearch.com/docs/user-guide/session-storage-recovery 를 먼저 확인합니다. WAL·SHM을 삭제하거나 DB 본체만 복사하지 말고, 백업과 해당 프로필의 쓰기 프로세스를 확인한 뒤 중지·복구·재시작은 별도로 승인된 점검 범위에서만 검토합니다. 문서 갱신만으로 자동 업데이트나 저장소 정리 명령을 실행하지 않습니다.
