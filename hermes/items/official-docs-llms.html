Hermes 공식 문서 갱신: 브라우저 도구 전환·플러그인 호환 조건 점검

Hermes Agent

지정 stable_id와 content_hash가 일치하는 후보의 raw URL을 직접 조회했고 원문의 제목 Hermes Agent를 보존했다. 공식 문서와 공식 저장소는 리디렉션을 따라간 최종 URL이 각각 원래 공식 URL이며 모두 HTTP 200임을 확인했다. 인덱스 갱신만으로 신규 기능을 단정하지 않고, 공식 저장소 main에 표시된 브라우저 전환과 플러그인 요구 버전 검사 변경을 근거로 운영상 의미가 있는 공식 문서 검토 항목으로 게시 승인한다. 안정 릴리스의 도입 버전은 확정하지 않는다. published_at은 문서의 별도 발행 시각이 아니라 후보에 기록된 HTTP Last-Modified 시각이며 collected_at은 후보 감지 시각이다.

핵심 요약

Hermes 공식 llms.txt에서 브라우저, 플러그인 카탈로그, 패키지 관리와 업데이트 안내의 현재 문서 경로를 확인했다. 함께 조회한 공식 저장소 main의 변경 설명에는 기존 browser_* 도구와 agent-browser 참조 정리, browser_exec 중심 전환, Chromium 패키지 관리 변경이 나타난다. 또한 플러그인 설치·업데이트 시 카탈로그의 requires_hermes 조건을 실제로 검사하는 변경이 확인된다. 이는 main의 개발 변경이며 특정 안정 릴리스나 현재 설치 환경에 이미 반영됐다는 뜻은 아니다.

왜 중요

단순 문서 인덱스 크기 변화만이 아니라 기존 브라우저 도구를 호출하는 자동화와 플러그인 설치·업데이트 경로에 영향을 줄 수 있는 운영 변경을 공식 저장소 https://github.com/NousResearch/hermes-agent 의 변경 설명과 대조했다. 문서 인덱스 자체에는 변경 이력이나 기능 도입 버전이 없으므로 문서 갱신과 안정 릴리스 배포를 구분해야 한다.

우리 영향

기존 browser_* 도구나 agent-browser 실행 경로에 의존하는 작업은 향후 업데이트 전 호환성 점검이 필요하다. 플러그인은 요구 Hermes 버전을 충족하지 않으면 설치가 거절되거나 업데이트가 보류될 수 있다. main 변경과 설치 버전의 적용 범위 차이, 브라우저 실행 경계와 호환성 우려는 escalation 후보로만 표시하며 확정된 보안 사고나 breaking release로 단정하지 않는다.

지금 할 일

공식 문서 갱신으로 게시하되 자동 설치·업데이트와 운영 설정 변경은 하지 않는다. 실제 도입 시에는 공식 Releases의 해당 버전 변경 내역, 브라우저 문서, 플러그인 요구 버전을 별도로 대조한 뒤 승인된 시험 환경에서 확인한다. 보안·breaking·문서와 저장소의 교차신호는 escalation 후보로만 관리한다.
