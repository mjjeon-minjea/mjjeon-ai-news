Hermes Agent v0.22.0 정식 공개: 안정 릴리스 채널·패키지 관리·프로필 게이트웨이 통합

Hermes Agent v0.22.0 — The Threshold Release

게시 승인: 지정 후보의 ID와 content_hash가 일치하고 draft 및 prerelease가 아닌 공식 릴리스다. 원문 제목과 공개 시각을 보존했으며, 공식 릴리스·Docs·repository의 최종 URL과 HTTP 200을 확인했다. 운영상 의미 있는 변경이 있어 공식 대표 후보로 적합하다. 게이트웨이 통합, 세션 정책과 플러그인 호환성 변경은 breaking 관련 escalation 후보로만 표시한다.

핵심 요약

Nous Research가 Hermes Agent v0.22.0 정식 릴리스를 공개했다. 공식 릴리스 노트에 따르면 소스 설치의 기본 업데이트 경로가 main 추적에서 검증된 SemVer 릴리스로 바뀌고, 통합 패키지 관리자 hermes pm은 새 의존성 환경을 검증한 뒤 전환한다. 머신당 하나의 게이트웨이와 데스크톱 백엔드가 여러 프로필을 처리하며, 관리형 설치의 런타임은 Python 3.14로 변경된다. 앱 커넥터와 llama.cpp 기반 로컬 모델 관리도 추가됐다.

왜 중요

단순 모델 추가가 아니라 업데이트 채널, 런타임, 의존성 관리와 다중 프로필 운영 구조가 함께 바뀌는 공식 릴리스다. 운영 중인 Hermes의 배포 재현성과 프로필 분리 설정, 세션 보존 정책에 직접 영향을 주므로 의미 있는 변경으로 선정했다.

우리 영향

공식 업그레이드 안내에는 프로필별 게이트웨이의 통합, session_reset의 idle/daily 모드 폐지, 종료 후 90일 동안 비활성인 세션의 자동 정리 기본 활성화가 포함된다. 열린 세션과 고정 세션은 정리 대상이 아니다. Python 3.14에서는 KittenTTS를 사용할 수 없고, 기존 플러그인 호환성 계층과 hermes sync가 제거돼 관련 사용자는 전환 전 호환성 확인이 필요하다. 기존 설치가 이미 이 버전으로 갱신됐다는 의미는 아니다.

지금 할 일

공식 릴리스와 Docs·repository를 기준으로 설정·세션·메모리를 백업하고 별도 검증 환경에서 업데이트 채널, 게이트웨이 통합, 플러그인과 세션 보존 동작을 확인한 뒤 적용 여부를 승인받는다. 세션 자동 정리를 원하지 않으면 sessions.auto_prune: false 설정을 검토한다. 보안·breaking·교차신호 조건은 escalation 후보로만 표시하며 이 뉴스 검토로 설치나 자동 업데이트를 실행하지 않는다.
