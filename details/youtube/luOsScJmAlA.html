  • 00:49–01:42 Recursive Language Model (RLM) 메모리 검색 방식: 방대한 컨텍스트와 메시지를 매 쿼리마다 전체 재독해(re-read)하여 발생하는 지연과 컨텍스트 팽창(Context Bloat)을 방지하고, 파일 캐비닛에서 필요한 문서만 검색해 꺼내는 방식 적용 영상에서 확인됨

  • 03:06–03:58 사후 자가 개선(Refine)을 통한 스킬 축적: 작업 완료 후 '시도한 것, 실패한 것, 성공한 것'의 3단계 사후 분석을 거쳐 해결책을 재사용 가능한 스킬(Skill)로 저장. 이는 모델 가중치 재학습(Retraining)이 아닌 에이전트 하네스/노트북 체계의 고도화임 영상에서 확인됨
  • 03:59–04:24 완전 자율 장기 실행 루프(Autonomous Long-running): 목표(Goal)와 종료 조건(최대 스텝 수, 검증 테스트 통과)을 지정하면 사람이 개입하지 않고 장시간 자체 오류 수정 및 점검을 반복 수행 영상에서 확인됨
  • 04:25–05:08 ARC-AGI-3 벤치마크 최고 수준 달성: 미경험 문제 해결력을 측정하는 ARC-AGI-3 평가에서 95.5%를 기록(인간 전문가 기준선 95.4% 상회), 3회 시도 허용 시 99.97%(183/183 전 레벨 완료) 달성 영상에서 확인됨

3. The Big Idea (핵심 아이디어)

기존 AI Agent의 병목과 RLM 아키텍처로의 전환

1. 제기하는 문제: 기존 대화형 및 에이전트 시스템은 50여 개의 도구 리스트를 프롬프트에 유지하고, 대화 이력과 데이터가 쌓일 때마다 문서 전체를 반복해서 읽어들입니다. 이로 인해 컨텍스트 윈도우 한계, 속도 저하, 세부 정보 유실이 필연적으로 발생합니다.


2. 제시하는 해결책: Prime Intellect가 제시한 Recursive Language Model (RLM) 구조는 도구 모음 대신 실시간 파이썬/노트북 환경을 제공합니다. 에이전트는 거대한 메모리를 직접 뒤지는 대신, 필요한 정보를 정밀하게 쿼리·필터링하는 스크립트를 직접 작성해 실행합니다.


3. 기존 방식과의 핵심 차이점: 모델 파라미터를 파인튜닝하거나 재학습시키는 것이 아니라, 작업 후 자가 반성(Refine)을 통해 문제 해결 스크립트와 패턴을 스킬 형태로 영구 보존합니다. 이는 "매주 뇌 이식을 받는 직원"이 아니라 "자신만의 검증된 업무 노트를 채워나가는 숙련된 직원"에 비유할 수 있습니다.


4. 결론 및 시사점: AI 에이전트가 스스로 코드를 수정하고 에러를 디버깅하며 스킬을 스스로 생성하는 환경이 실무에 진입하고 있으며, 도구 자체의 파괴적 발전 속도에 맞춰 워크플로우를 사전에 테스트하고 통합하는 준비가 필요합니다.

5. Key Concepts & Technology (핵심 개념 및 기술)

Recursive Language Model (RLM)

영상에서의 의미: 거대 언어 모델이 거대한 컨텍스트 데이터를 통째로 프롬프트에 담아 읽는 대신, 메모리를 일종의 구조화된 파일 시스템으로 취급하여 파이썬 코드를 통해 필요한 부분만 재귀적·프로그래밍 방식으로 질의·추출하는 아키텍처 패러다임.

Live Coding Workspace (단일 실행 환경)

영상에서의 의미: 50개의 개별 도구 API를 나열하는 대신, 에이전트에게 단 하나의 라이브 코딩 인터프리터(노트북 환경)를 제공하여 검색, 필터링, 위임, 계산 등 모든 행위를 코드로 작성하고 즉시 실행하게 만드는 인터페이스.

Sub-agent Parallel Delegation (하위 에이전트 병렬 위임)

영상에서의 의미: 복합 프로젝트를 세부 작업(모듈 점검, 연동 테스트 등)으로 분할하여 여러 개의 미니 에이전트를 동시에 생성·병렬 실행한 뒤 결과를 종합 취합하는 구조.

Self-Refinement & Skill Extraction (자가 반성 및 스킬화)

영상에서의 의미: 작업 완료 후 에이전트가 "무엇을 시도했고, 무엇이 실패했으며, 무엇이 작동했는가"를 자체 회고하고, 검증된 해결 패턴을 영구적인 재사용 가능 스킬(Skill)로 저장하는 하네스 기능.

Agent Harness vs Model Retraining

영상에서의 의미: 모델 자체의 신경망 가중치를 재학습시키는 것이 아니라, 모델 주변의 메모리 관리, 스킬 축적, 툴 인터페이스 환경(Harness)을 고도화하여 에이전트의 실질적 성능을 향상시키는 구조적 분리 원리.

7. Workflow & How-To (작업 절차 및 워크플로우)

1

목표(Goal) 및 종료 조건 설정

에이전트에게 수행할 최종 목표를 입력하고, 최대 스텝 수(Max Steps) 또는 반드시 통과해야 하는 검증 테스트(Check/Pass Criterion)를 지정합니다.

2

RLM 기반 데이터 필터링 및 서브에이전트 분기

에이전트가 단일 라이브 코딩 환경에서 필요한 메모리/데이터만 쿼리하는 스크립트를 작성하고, 독립된 하위 작업을 담당할 Sub-agent들을 병렬로 생성합니다.

3

자율 실행 및 디버깅 루프 (Try-Test-Fix Loop)

시도 → 테스트 → 에러 발생 → 코드 수정 → 재테스트 과정을 자율적으로 반복하며 설정된 통과 조건이 충족될 때까지 실행을 지속합니다.

4

Refine(사후 분석) 3단계 질의 실행

작업 완료 후 '무엇을 시도했는가?', '무엇이 실패했는가?', '무엇이 성공했는가?'의 3대 자가 질문을 통해 성공 요인을 정리합니다.

5

스킬(Skill) 저장 및 차기 작업 재활용

정리된 해결책을 재사용 가능한 스킬 파일로 저장하여, 향후 유사 문제가 발생했을 때 처음부터 탐색하지 않고 즉시 검증된 솔루션을 적용합니다.

8. Prompts & Commands (핵심 프롬프트 및 질의 프레임워크)

Refine 메커니즘의 3대 핵심 질의 프레임워크

Prime Agent가 태스크 완료 후 스킬을 생성할 때 내부적으로 스스로에게 묻는 3가지 질문 원문:

1. "What did I try?" (내가 무엇을 시도했는가?)
2. "What failed?" (무엇이 실패했는가?)
3. "What actually worked?" (무엇이 실제로 작동했는가?)

활용 원리: 에이전트는 이 3단계 답변을 구조화하여 다음 작업 시 참조할 수 있는 스킬 레시피로 영구 기록합니다.
